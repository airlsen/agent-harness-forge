# Forge 前端产品体验改造方案

> 产品方案 v0.4 · 2026-11-17
> 根据用户明确的企业共享前提重写，取代 v0.1 中偏个人工作空间的组织假设；v0.3 纳入页面布局简化；v0.4 以最新批准的“保留工作台、对话优先”方案为准，取代首页目录式陈列。
> 本文件记录产品目标与布局约束；实际实现、验收和未交付边界见《09》，不把目标能力当作现状。

## 0. 已确认的产品前提

**产品是同一家企业内部大家一起使用的 Agent 平台，不是给每个员工创建一个私人 Agent 工作空间。**

- 企业统一提供场景、Skills、MCP 服务、业务工具、插件和模型连接。
- 这些资源默认作为企业公共资产发布，员工引用使用，不各自重复安装或配置一份。
- 会话按员工隔离；会话上下文、消息、附件、产物、执行记录和审批记录跟随会话隔离。
- 公共是“企业内部共享”，不是互联网公开，也不是公开访问密钥或无限制业务数据。
- 暂不引入个人空间、部门空间、多空间切换和多租户 SaaS 结构。

一句话定位：

> **企业共享能力平台，员工在各自会话中调用公共能力完成工作。**

使用体验可以类比企业公共服务门户：服务和规范由企业统一提供，个人办理过程与记录独立；不是每人维护一套自己的服务平台。

## 1. 相比上一版，必须实质修正什么

| 上一版倾向 | 本版修正 |
|---|---|
| 用个人工作空间组织整个产品 | 企业统一平台；账号只标识当前员工，不代表一个私有资源空间 |
| 工作台 / 工作场景 / 我的任务为主要前台 | 工作台 / 企业场景 / 企业能力中心，加个人会话区 |
| Skills、MCP 和能力主要收进管理区 | 发现与使用在公共前台；配置、维护、发布操作受权限控制 |
| 官方 / 我的场景作为主要归属分类 | 企业已发布场景为公共目录；创建者是维护责任信息，不等于私有资产 |
| 插件安装后再分发到个人空间 | 平台安装和发布一次，授权会话按需引用，不按人重复安装 |
| 用“我的”修饰场景、插件、技能等 | “我的”只用于会话和会话相关记录，不建立个人 Skills 库或个人 MCP 目录 |

**企业化不能只体现在后台治理菜单多，也要体现在员工能发现、理解和复用共同资产。**

## 2. 先区分三个问题：归属、维护和执行

### 2.1 资产归属企业

场景、Skills、MCP 服务定义、业务工具、插件版本、模型连接、平台策略归企业。资源应有稳定 ID、维护责任人、版本、发布状态、适用说明。

创建者 / 维护人用于协作和追责，不应自动把资产变成“只有本人可见”。未发布草稿属于企业资产的维护状态，不是给员工另开一个私人资源空间。

### 2.2 维护权限可以不同

全员使用不等于全员可以修改生产连接或发布执行代码：

- 员工：查看和使用企业已发布资产，管理自己的会话。
- 能力维护者：维护被授权的场景、Skills 或连接，测试并按流程发布。
- 平台管理员：管理模型和凭据、资产准入、企业策略与运维。

这是同一个企业平台中的职责划分，不是多套资源空间。是否允许全员提交草稿可后续配置，不影响企业统一归属。

### 2.3 执行属于当前会话

```text
企业公共资源
├─ 报告整理 Skill v3
├─ 工单 MCP 服务
├─ 文档与报告场景 v2
└─ 企业模型连接
       │
       ├─ 员工 A → 会话 A → A 的消息、附件、执行记录和文件
       └─ 员工 B → 会话 B → B 的消息、附件、执行记录和文件
```

两人引用相同 Skill 和同一 MCP 服务定义，但不能因此读到对方会话。企业公共 Skill 也不能默认把某个员工的聊天内容、业务记录或生成文件纳入公共知识。

## 3. 推荐信息架构

```text
Forge · 企业智能体平台
│
├─ ＋ 新建会话
│
├─ 工作台                        统一自然语言工作起点，保留独立页面和默认路由
├─ 企业场景                      企业发布的工作方式、SOP 和应用入口
├─ 企业能力中心                  人人可发现的公共资产目录
│   ├─ Skills（技能）
│   ├─ MCP 服务
│   └─ 插件与工具
│
├─ 我的会话                      唯一主要的个人内容区
│   ├─ 搜索 / 查看全部
│   └─ 最近会话（侧栏少量快捷项，纯文字分组，无箭头/展开控件）
│
└─ 平台管理                      按职责显示管理操作
    ├─ 公共资产维护               进入同一资源的管理视图，不复制目录
    ├─ 模型与凭据
    ├─ 成员与权限                 需真实多用户身份与授权实现
    ├─ 企业策略
    └─ 运营与授权审计
```

设计要求：

1. 左侧顶部显示企业或平台标识，不另设重复全局顶栏，不提供“我的空间 / 团队空间 / 新建空间”切换器。
2. 企业能力中心是一级产品入口，不再把全部能力藏进后台。
3. 左侧“我的会话”是个人记录区，不扩张成“我的 Skills / 我的 MCP / 我的插件”。
4. 企业场景与能力中心面向全员；编辑、发布和配置按钮按真实权限出现。
5. 平台管理可保留专业表单和诊断，但员工日常无需进入。
6. 一个资源只有一份目录和详情，通过使用 / 维护视图区分动作，不复制“公共能力库”和另一份独立“管理库”。

### 3.1 页面外壳与标题：已批准的简化约束

- 删除重复的“企业平台 ＞ 当前页”、全局“单管理员预览”和“使用指南”顶栏，连同 60–64px 占位一起删除；不补空栏、搜索或通知等未要求的控件。
- 帮助改为左侧底部的次级入口，内容是实际操作说明；身份和部署限制保留在登录、平台管理及会话等相关位置，不用全站重复徽标打断任务。
- 保留工作台菜单与默认落点，用“今天要完成什么工作？”及居中输入直接开始；移除副标题、英文宣传、插图、首页能力/最近工作模块和场景目录式陈列。只保留约 3 个真实轻量场景建议、输入控件及必要的连接/错误提示；资源与历史由侧栏继续提供。
- 常规页保留一组标题、必要说明及页级动作，统一顶部间距与内容网格；轨迹页额外保留返回导航，会话页保留业务工具栏，管理页保留二级导航。
- 左侧菜单继续常驻、图标文字对齐、主次字重清楚；暖橙主题和本地线性 SVG 规则不变。这是布局收敛，不是另一次换主题。

## 4. 企业能力中心：从技术组件清单改成可用资产目录

### 4.1 普通员工看到什么

卡片或轻量列表应回答：

- 它能帮我完成什么？
- 适用于什么问题？
- 有哪些使用规范或示例？
- 企业已经接好了吗？当前是否可用？
- 会访问哪个业务系统，哪些操作需要确认？
- 由谁维护、目前是什么版本？
- 从哪个企业场景可以开始使用？

不应默认展示包路径、原始工具 Schema、密钥字段和内部运行日志。

### 4.2 资源分类与可见内容

| 分类 | 员工可见的公共内容 | 维护者额外操作 |
|---|---|---|
| Skills | 业务说明、输入与输出示例、工作规范、版本、适用场景 | 编辑资源、测试、发布、维护版本 |
| MCP 服务 | 服务用途、提供的业务工具、可用状态、使用边界、适用场景 | 配置地址与认证、测试连接、维护工具范围、停用 |
| 插件与工具 | 提供哪些动作、读写属性、确认要求、使用说明 | 审核安装、配置、发布版本、停用 |

企业场景是一组公共工作规范与能力的预配置组合，不与 Skills、MCP 重复混成一份“智能体清单”。dsh SDK 等基础设施组件放平台高级信息，不作为普通员工可安装的业务应用。

### 4.3 资源不是每人安装一遍

避免按钮：“安装到我的空间”“创建我的 MCP 副本”。

目标按钮：

- 员工：查看使用说明、查看适用场景；当运行时引用机制具备后，可在新会话中使用。
- 场景维护者：添加到企业场景。
- 平台维护者：配置、测试、发布、版本、停用。

其中注册、安装、动态挂载和 Skills / MCP 执行目前尚未完成，不能在本轮前端换版时做成假操作。

## 5. 工作台：保留统一起点，让用户进入就能表达目标

**保留“工作台”一级菜单、独立页面与默认路由，不采用删除菜单后重定向到新建会话的方案。** 工作台是统一工作入口；“新建会话”是主动开始独立上下文的动作，二者不等同。

首页不再承担场景目录和公共能力宣传页的职责。平台的企业属性来自真实资源、治理和执行机制，而不是输入框下面重复摆一遍所有入口。

```text
┌──────────────────┬──────────────────────────────────────────────┐
│ 企业平台标识      │                                              │
│ ＋ 新建会话       │           今天要完成什么工作？               │
│                  │                                              │
│ 工作台           │    ┌────────────────────────────────────┐    │
│ 企业场景         │    │ 描述目标、已有信息与期望结果……     │    │
│ 企业能力中心     │    │                                    │    │
│ 我的会话         │    │ 场景选择   附件             发送 ↑  │    │
│                  │    └────────────────────────────────────┘    │
│ 最近会话         │    必要时显示可操作的模型连接/错误提示        │
│ · 少量真实记录   │                                              │
│                  │    [文档与报告] [代码与研发] [分析与决策]    │
│                  │                                              │
│ 平台管理 / 帮助  │                                              │
│ 当前账号         │                                              │
└──────────────────┴──────────────────────────────────────────────┘
```

### 5.1 首页删什么、保留什么

删除首页的“企业公共能力”“继续最近的工作”（含空状态/列表/全部会话链接）、宣传页脚、标题副文案、场景目录标题/说明/全部场景链接、大卡片的描述/来源/版本/背景块和悬停箭头。

保留：一个标题、约 760–840px（实现取 820px）的输入区域、附件/真实场景选择/发送、必要连接和加载/失败状态，以及约 3 个真实非默认场景按钮。手机与软件键盘/短窗口优先保证可输入、可发送和可滚动，不拘泥垂直正中。

企业场景、公共能力、最近会话与完整记录的真实页面和 API 都保留在侧栏路径，不因首页精简而被删除。

### 5.2 选择、发送与持续交互

- 快捷按钮只取实际预置/已发布场景，排除默认通用场景；缺少就少显示，不伪造能力或补空卡。
- 点击在当前页选中场景并聚焦输入。不得跳转、自动提交、提前创建会话或覆盖已有文字和附件；本次不自动塞入示例，完全保留用户输入。
- 首条消息被服务端接受后直接进入实际持续会话，输入移到底部，起始建议退出，不再经历第二个欢迎/选择步骤。首轮失败保留起始输入和附件，可在原上下文重试。
- 空白新会话复用同一个起始组件，不维护两套欢迎页；实际会话保留结果、过程、审批、文件、导出和快照等必要工具。

### 5.3 草稿与执行状态不能被导航破坏

起始草稿与每个既有会话的回复草稿分开，返回工作台不混入旧上下文；回到原会话只恢复该会话自己的输入和附件。显式新建若会替换未发送的起始草稿，应提供取消、返回草稿和明确放弃，不能静默丢弃。

草稿在当前登录标签页内存中保存，退出/认证失效清空。不将业务正文和附件写入浏览器持久存储；刷新/离站由浏览器确认提醒，但不承诺跨刷新恢复。迟到创建/提交回执、失败/取消的历史读取与附件异步读取均需有上下文保护。

返回首页或离开 SSE 页不代表中止后台执行，不能调用 interrupt；状态列表应能在后台结算后刷新。提交还未确认时显示忙状态，不假装已经执行或提供无效的中止按钮。

### 5.4 工作台未来的空间，不等于本轮新增看板

工作台保留后续跨工作协调的产品位置，但只有真实任务机制、授权、调度和持久状态具备后，才讨论待处理工作、成果通知或跨会话协同。本轮**不新增待办/运行看板/公告/使用量/Token 卡片或未来能力占位**。

“企业公共”不意味着首页展示全员对话或把别人的附件、产物变成公共内容。当前单管理员版本仍明确披露员工访问隔离尚未交付。

## 6. 员工怎样选择公共能力

提供两条路径，而不是强迫每个人都懂底层装配。

### 路径 A：使用企业场景

选择“文档与报告”等已发布场景 → 场景已带好企业公共 Skill 和必要工具 → 输入任务 → 执行 → 查看自己的结果。

适合普通员工，默认不逐个勾选技术服务。

### 路径 B：新会话按需引用公共能力

高级用户新建会话 → 从企业公共能力库选择已发布资源 → 查看本次使用范围 → 发起会话并锁定引用版本。

**这是引用公共资源，不是复制出一份私人 Skill 或私人 MCP。** 当前后端尚不支持任意 Skills / MCP 装配，因此该交互属于后续接入目标，不能仅前端开放。

两条路径共享同一企业资源目录和治理规则。

### 关键边界：企业共享不等于每个会话全量挂载

即使全员都能使用公共 MCP，也不应把企业所有工具和 Skill 全部塞进每个模型请求。需要按场景或新会话选择相关能力，减少工具歧义、上下文负担和不必要的数据访问。

选择器中的摘要应表达业务能力；例如“接口文档查询、报告规范”，原始 MCP 名称和 Schema 放详情。公共能力始终可被找到，但不占满日常输入框。

## 7. 企业场景：共同维护，不是个人应用仓库

场景卡片主要展示适用工作、预期输出、使用说明和“开始会话”，辅以企业共享、维护人、版本和发布状态。

默认浏览企业已发布场景。具备职责的人员进入同一对象的维护视图，进行编辑、装配能力、试运行和发布。

不把“官方 / 我的 / 团队空间”作为本版主信息架构。可以保留“平台预置 / 企业自建”来源标签和“由我维护”管理筛选，但它们不改变企业归属和发布后的全员可用性。

维护流程建议：

```text
维护者创建或修改 → 测试 → 按企业规则发布
                         ↓
                 全员在同一目录发现并引用
```

“共享给企业”不是每个资源都要额外执行的个人分享动作，企业发布本身就是进入公共目录。

## 8. 会话页与隐私边界

会话继续采用“对话主线 + 结果 / 过程按需查看”，但加强两种归属的区分：

- 来源区域：“使用了企业场景 v2、报告 Skill v3、企业 MCP 服务”。
- 内容区域：当前员工本次会话的消息、操作、确认和文件。

公共资源更新不会把 A 员工的上下文带给 B 员工。历史引用版本用于解释执行，不是把私人聊天作为公共资源的一部分。

### 8.1 跟随会话隔离的对象

- 用户消息、模型回复和上下文；
- 附件和会话工作目录；
- 文件产物与内容预览；
- 事件流、工具结果和轨迹；
- 会话快照、导出包和待确认操作。

后续如果允许分享结果或沉淀到企业知识，需要明确、独立的发布动作和授权，不能自动变成公共内容。

### 8.2 审计不是全员聊天浏览器

平台可查看必要的运行状态与汇总用量。访问会话正文、文件或原始参数应有独立的审计授权、企业规则和访问记录，不因为具备资产维护权就能随意查看所有人的会话。

### 8.3 不虚构任务完成与执行恢复

现阶段会话承载个人工作，不另建尚未实现的任务调度中心。`idle` 表示可继续 / 本轮结束，不自动等于业务目标成功完成。批量、定时、原生 fork 和跨 Runner 执行恢复仍需真实后端能力。

## 9. 共享 MCP 特别需要说清的边界

**共享的是服务登记、接入配置和可用工具，不是把密钥和所有业务数据公开给每个员工。**

- 凭据由企业托管，普通员工不能查看或导出原文密钥。
- 企业可以使用统一服务账号；若业务系统需要按员工限制数据，应采用用户委托认证或服务端可信授权，不能把模型传入的 userId 当作鉴权依据。
- 如果上游只有一个全权服务账号且没有可靠的数据授权，平台不能仅靠前端显示“个人会话”就保证业务数据隔离；应限制暴露范围或补充执行侧校验。
- MCP 协议的执行状态、用户委托令牌和敏感缓存要按用户 / 会话正确隔离，不能把它们作为全局可变状态混用。
- 写入审批归属实际发起会话或明确的审批人，不能因为服务公共就让任意员工批准他人操作。

企业级使用必须同时区分：资源可发现、资源可使用、资源可维护、业务数据可访问。这些不必设计成多个空间。

## 10. 版本与停用：共享但不能互相干扰

- 企业维护公共 Skill / 场景 / 插件版本，新会话使用新发布版本。
- 已开始会话记录原引用，常规升级不能静默改写正在执行的配置。
- 停用、凭据撤销和紧急安全封禁必须有服务端实际执行机制；不能以“快照已锁定”为理由继续允许已撤销的危险操作。
- 被停用资源在企业能力库中解释不可用原因，并告知受影响会话如何新建或更换。

这些是后续实现要求，不代表当前所有资源类型已经支持版本发布和实时撤权。

## 11. 使用与维护共用一套页面对象

| 页面 | 全员默认视图 | 有职责的人员增加的操作 |
|---|---|---|
| 企业场景 | 浏览、说明、开始会话 | 编辑、试运行、发布、版本 |
| 企业能力中心 | 企业公共资源、用途、状态、使用路径 | 注册、配置、测试、版本、停用 |
| MCP 详情 | 服务用途、业务工具、访问边界 | 地址与认证配置、连通性检查、范围维护 |
| Skill 详情 | 规范说明、适用工作、示例、版本 | 内容与资源维护、验证、发布 |
| 我的会话 | 当前员工自己的记录 | 仅对自身会话操作；跨人审计另走授权入口 |
| 平台管理 | 无管理职责时不开放管理动作 | 成员、模型与凭据、策略、运行维护、授权审计 |

同一个资产 ID、同一资源详情、同一版本来源，不做两份独立资产库。前端根据后端能力显示相应动作，而不是用菜单隐藏来代替鉴权。

## 12. 视觉表达的调整

保留“任务输入优先、清晰正文、克制色彩、少层级卡片”的方向，但不再把页面包装成个人效率助手。

- 品牌与稳定侧栏体现企业平台定位；首页只突出自然语言输入，不用公共能力宣传文案打断任务，也不使用“我的私人空间”。
- 企业场景和公共能力的发现具有稳定位置，不全部沉入管理台。
- 公共资源显示企业共享、维护人、版本和状态；个人会话显示自己的标题与执行状态。
- 不用“你好，开发者”作为全员默认身份，也不假设员工要自己连接模型和安装服务。
- 只有真实权限隔离落地后才能显示“仅你可见”；当前单管理员预览不能用一个锁图标假装实现。
- 桌面右侧详情按需打开；左侧导航按最新用户要求始终显示，桌面/平板为完整侧栏，手机保留图标与文字的常驻窄栏，不采用点击展开的导航抽屉。不把企业资源目录硬塞进聊天输入框。

## 13. 当前实现与企业目标之间的真实差距

当前运行版本仍为单管理员业务验证版，尚不能因为前端改名就向全公司宣称已经支持个人会话隔离。

实际需要补齐：

1. **真实员工身份**：独立账号或企业 SSO，服务端能识别当前 userId；不是大家共用 admin。
2. **会话归属校验**：创建绑定登录用户；列表、详情、SSE、文件、导出、审批和写入接口都检查归属。
3. **公共资产模型**：企业拥有资源；维护人 / 创建者是职责元数据，不默认按 ownerId 过滤成私人目录。
4. **职责与操作权限**：普通员工使用，维护者维护，管理员管凭据与策略；所有入口由服务端校验。
5. **Skills / MCP / 插件动态接入**：当前尚未实现的能力需要真实注册、凭据托管、装配和执行。
6. **企业并发验证**：共享一套平台后，要按预期并发检验 Runner 容量、隔离和资源限制；当前默认容量 4，不等于企业负载验收。

当前代码的明确边界：会话服务仍使用固定管理员身份，列表和会话读取没有多员工所有权模型；预览认证解决的是登录传递问题，不是企业身份系统。

因此，已批准的自然语言入口可先于员工身份建设落地，但“全员上线、个人会话独立”的交付必须包含最小多用户身份与服务端隔离，不能只改前端展示。

## 14. 建议实施顺序

### A. 已确认并实施的企业共享版入口骨架

先在现有业务应用中完成四类页面：

- 企业工作台：自然语言统一起点，公共目录和个人会话从稳定侧栏进入；
- 企业能力中心与公共资源详情；
- 企业场景与维护视图；
- 个人会话执行页：引用公共能力，内容独立。

不另建个人空间、个人插件库或“安装到我的空间”，不把原工作台替换为菜单重定向。

### B. 建立最小真实身份与隔离，再承诺企业多人使用

确定员工身份接入方式，完成用户归属和操作权限；现有管理员数据明确迁移到原账号，不能把旧会话自动公开。验证员工 A 无法读写员工 B 的消息、流、文件、审批和导出。

不要求第一步做完整多租户体系，但不能跳过单企业内的多用户隔离。

### C. 前端改版与公共目录产品化

基于真实用户与统一资产目录落地导航、企业首页、能力发现、场景引用和个人会话。保留已有认证兼容、流式恢复、审批、文件和导出能力，不重写 Harness 内核。

只在后端支持时开放 Skill / MCP 的选择、测试、发布、装配等动作。

### D. 深化公共能力运营与连接治理

可信插件闭环、Skills / MCP 接入、版本发布、实际连接权限和企业并发验证。企业能力新发布一次，员工在同一目录发现和引用，而不是每人重配一遍。

## 15. 验收标准（目标，不代表已实现）

1. 两名员工看到同一企业已发布 Skill、MCP 和场景目录。
2. 企业资产只维护一份；修改维护人不使资源变成私人资产。
3. 员工 A 的会话默认不出现在员工 B 的列表、搜索、待办或结果中。
4. 即使 B 知道 A 的会话 ID 或文件 URL，也不能读取、订阅、导出、审批或修改。
5. A、B 引用相同公共能力时，上下文、协议状态和敏感数据不串用。
6. 普通员工可理解公共能力的用途与使用路径，不必进入后台配置地址和凭据。
7. 普通员工不能读到共享密钥、修改连接配置或安装未经批准的执行代码。
8. 新会话引用公共资源的行为不会生成一份默认私有副本，也不会默认全量挂载所有工具。
9. 公共资源升级与停用有可解释的行为，快照留存不妨碍安全撤权。
10. 当前单管理员、Skills / MCP 未接入等状态被如实展示，不用 UI 标签冒充企业能力完成。

## 16. 最终结论

**企业资产共用，员工会话独立；公共能力在前台可发现，配置维护按职责开放。**

这比“给每人一个工作空间”更符合当前定位，也比“所有人面对一个聊天框”完整。

本版方案后续统一使用“企业平台 / 企业场景 / 企业能力中心 / 我的会话 / 平台管理”的产品语言，不再沿用偏个人工作空间的资产组织。
