# 空间

> v1.0 · 2026-11-22
> 本方案修订《08》中“暂不引入部门空间和多空间切换”的前提：平台仍是**同一家企业共用**的，不做个人空间，也不做多租户 SaaS。新增的「空间」用来按团队或业务划分内容。

## 目标与范围

企业里的场景、Skill、MCP 服务和插件越来越多以后，全部放在一起会很难找，也容易误用。空间把它们按团队或业务（例如“财务部”“研发中心”）分开：

- 在某个空间里，只能看到**本空间 + 公共空间**的内容。
- 新建的内容放进当前空间；已有内容可以移动到其他空间。
- 每个空间可以关闭一部分基础工具，但只能在执行策略允许的范围内收紧。

空间**不是权限边界**。所有登录用户都可以切换到任何空间，也都能管理空间（与“执行策略”“模型连接”等平台管理页面一致）。它解决的是“分类与默认范围”，而不是“谁能看”。

| 内容      | 归属空间 | 在别的空间可见吗                         |
| --------- | -------- | ---------------------------------------- |
| 场景      | ✓        | 只在本空间；公共空间的场景所有空间都可见 |
| Skill     | ✓        | 同上                                     |
| MCP 服务  | ✓        | 同上                                     |
| 插件      | ✓        | 同上（同一插件的全部版本在同一空间）     |
| 会话      | ✓        | 只在所在空间，公共空间也不例外           |
| 基础工具  | 开关     | 每个空间单独开关，默认全部开启           |
| 模型/策略 | 全局     | 所有空间共用                             |
| 运行审计  | 全局     | 显示全部空间，可以按空间筛选             |

## 公共空间

- 内置，编号固定为 1，名称“公共”，灰色。
- 不能删除、改名或改颜色，只能修改说明。
- 升级时所有已有内容（含预置场景、内置插件、已有会话）都归入公共空间，行为与升级前完全一致。
- 平台预置场景（`space=official`）始终在公共空间，不能移动。

## 切换空间

- 位置：左下角账号菜单。头像右侧第二行显示当前空间（色块 + 名称）；菜单顶部列出全部空间，当前空间打勾，下面是“管理空间”。空间超过 6 个时出现搜索框，列表限高滚动。
- 前端把当前空间编号记在本地存储（`forge.space.v1`，只存编号和名称），每个 API 请求带 `X-Forge-Space` 请求头。
- 切换后：侧栏最近会话、场景、基础工具和扩展能力选项立即按新空间刷新，当前页面重新挂载。正在查看某条具体内容（会话、插件详情、Skill 编辑）时回到对应列表页，因为它可能不属于新空间。
- 新会话草稿里选的场景、临时选择的 Skill / MCP 不在新空间时会被移除；已有会话不受影响。
- 记住的空间被别人删除后，下次打开时回到公共空间并提示。

### 打开别的空间的内容

通过链接（或“我的会话 · 全部空间”）打开别的空间的会话、插件或 Skill 时，**自动切换到它所在的空间**并提示“已切换到「X」（会话所在空间）”，停留在当前页面。这样会话继续时使用的扩展能力和工具开关与它所在空间一致。

## 后端规则

### 请求头

`X-Forge-Space` 由依赖 `current_space` 读取：

- 不带请求头：`None`，不做空间过滤（兼容旧客户端和脚本，行为与升级前一致）。
- 编号无效或空间已删除：按公共空间处理。

### 可见性

- 场景、Skill、MCP、插件列表：`space_id IN (当前空间, 公共)`。
- 会话列表：只列 `space_id = 当前空间`；`GET /api/agent/sessions?space=all` 列出全部空间（“我的会话”的“全部空间”视图）。
- 审计：始终全局，`GET /api/audit/sessions?space_id=` 可选筛选。

### 新建内容放在哪里

| 操作                    | 放入的空间                                     |
| ----------------------- | ---------------------------------------------- |
| 新建场景                | 当前空间；预置场景在公共                       |
| 复制场景 / 基于模板创建 | 当前空间（没有当前空间时为原场景所在空间）     |
| 新建 Skill              | 当前空间                                       |
| 导入 MCP 服务           | 当前空间                                       |
| 上传插件（新插件）      | 当前空间                                       |
| 上传插件（新版本）      | 跟随插件已有的空间；从别的空间上传返回 409     |
| 新建会话                | 场景在当前空间可见时为当前空间，否则为场景空间 |

### 引用规则

- 场景只能绑定**所在空间和公共空间**的 Skill、MCP 和插件；保存时校验，违反返回 422 并列出不可用项。
- 聊天里临时选择的 Skill / MCP 同样以会话所在空间为准。
- 场景编辑器只列出场景所在空间可用的选项；已绑定但不在本空间的项显示“不在本空间”，取消勾选后才能保存。

### 名称

- **Skill**：在任何空间里能同时看到的 Skill 不能重名（不区分大小写）。放进普通空间时，不能和本空间、公共空间的 Skill 重名；放进公共空间时，不能和任何空间的 Skill 重名。
- **MCP 服务**：名称全局唯一（运行时用名称区分工具）。导入的名称已存在于看不到的空间时返回 409，并说明在哪个空间。
- **空间**：名称唯一（不区分大小写），最多 20 字；说明最多 100 字；颜色从 8 种里选，不选时自动挑一个还没用过的。

### 基础工具开关

- 每个空间保存一份“已关闭的基础工具”（`Space.disabled_tools`）。
- 实际可用 = 执行策略 `allowedTools` − 本空间关闭的工具。空间只能收紧：执行策略未允许的工具不能在空间里开启（409）；未知工具返回 404。
- 新会话的执行策略快照里，`allowedTools` 已去掉本空间关闭的工具（`space_service.effective_policy`），Runner 以它为基础能力上限，因此默认补齐的基础能力也会被关闭。
- 只影响**新建会话**；已开始的会话继续使用启动时的快照，与执行策略一致。
- 关闭前提示本空间里用到该工具的场景（`GET /api/spaces/{id}/tools/{tool}/usage`）。
- `GET /api/registry/tools` 按当前空间返回 `policyAllowed`、`spaceEnabled`、`available`。

## 移动

场景、Skill、MCP 服务和插件都可以移到其他空间（插件的全部版本一起移动）。先检查再移动：

`POST /api/spaces/move/check` → `{blockers, conflicts}`，两者都为空才能 `POST /api/spaces/move`。

| 情况                                                        | 结果                                     |
| ----------------------------------------------------------- | ---------------------------------------- |
| 场景依赖的 Skill / MCP / 插件在目标空间用不到               | 不能移动，列出这些依赖                   |
| Skill / MCP / 插件移到普通空间，但其他空间的场景仍在使用它  | 不能移动，列出这些场景（移到公共总可以） |
| Skill 移过去后与目标空间能看到的 Skill 重名                 | 不能移动，先改名                         |
| 场景移动后                                                  | 已有会话留在原空间，新会话在目标空间     |

## 删除空间

- 删除时空间里的内容**整体转移**到另一个空间（默认公共），包括会话；不提供“连内容一起删除”。
- 转移会造成 Skill 重名时不能删除，先改名或换一个转移目标（`GET /api/spaces/{id}/delete-check?target=`）。
- 基础工具开关随空间删除。
- 删除的是自己当前所在空间时，前端回到公共空间。

## 接口

| 方法   | 路径                                   | 说明                                 |
| ------ | -------------------------------------- | ------------------------------------ |
| GET    | `/api/spaces`                          | 空间列表（公共在前），含各类内容数量 |
| POST   | `/api/spaces`                          | 新建空间                             |
| GET    | `/api/spaces/{id}`                     | 空间详情                             |
| PUT    | `/api/spaces/{id}`                     | 修改名称、颜色、说明                 |
| GET    | `/api/spaces/{id}/delete-check?target=`| 删除前检查                           |
| DELETE | `/api/spaces/{id}?target=`             | 删除并转移内容                       |
| GET    | `/api/spaces/{id}/tools`               | 基础工具开关                         |
| GET    | `/api/spaces/{id}/tools/{tool}/usage`  | 本空间里用到该工具的场景             |
| PUT    | `/api/spaces/{id}/tools/{tool}`        | 开启 / 关闭 `{enabled}`              |
| POST   | `/api/spaces/move/check`               | 移动前检查 `{kind, id, targetSpaceId}` |
| POST   | `/api/spaces/move`                     | 移动                                 |

列表和详情里的内容带 `spaceId`（场景和会话另带 `spaceInfo`：编号、名称、颜色、是否公共），扩展能力选项带 `isPublic`。

## 数据与升级

- 新表 `space`（`id`、`name`、`color`、`description`、`is_public`、`disabled_tools`、`created_at`、`updated_at`）。
- `agent_scenario`、`skill`、`mcp_server`、`plugin_registry`、`agent_session` 增加 `space_id` 列（默认 1，带索引）。
- 启动时 `init_db()`：`create_all` → `ensure_space_columns`（为旧库补列，已有行取默认值 1）→ `ensure_public_space`（创建公共空间）。旧库无需手工迁移。

## 前端

- 账号菜单：当前空间、切换、管理空间。
- 平台管理 → **空间管理**（`/agent/spaces`）：左侧空间列表，右侧详情（内容数量、基础工具开关、编辑、删除并转移）。新建对话框说明“新空间是空的、公共内容都能用、新建内容放进这里”，创建后询问是否切换过去。
- 列表里来自公共空间的内容显示“公共”小标记（当前就在公共空间时不显示）。
- 场景、Skill（我的技能）、MCP 服务的“更多”菜单和插件详情页提供“移动到其他空间”。
- 我的会话：“当前空间 / 全部空间”切换，全部空间视图多一列“空间”。
- 运行审计：多一列“空间”和空间筛选。
- 空间色块使用 `--space-*` 颜色 token（`styles/tokens.scss`），不在组件里写颜色值。

## 不做

- 空间级权限（谁能进入、谁能管理）。
- 个人空间、多租户。
- 模型连接、执行策略按空间区分。
- 会话随场景一起移动。
