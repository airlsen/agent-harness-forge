# 用户体验原则审查（rev-1.0.0）

原则：复杂留给系统，用户专注于目标和判断。检查范围包括工作台、会话、场景、技能、能力、模型连接、执行策略、空间、运行状态与审计的路由及关键交互；以实际前后端代码为准。

| 原则 | 当前处理与本次修复 | 后续验收重点 |
| --- | --- | --- |
| 系统能判断的，不留给用户 | 新会话自动选择可用模型；缺少模型时保留输入，并提供配置入口，不强制跳页。 | 场景与能力的默认选择应以实际可用性为依据。 |
| 此刻没用的，就不出现 | 运行状态和审计放在平台管理；会话执行中主操作显示中止，结束后恢复发送。 | 逐页检查空状态是否仍展示无效操作。 |
| 能替人做的，就直接做 | 会话断线续读、草稿切换保留和闲置后接续由系统处理；本次修正闲置回收误删 Runner 会话句柄。 | 真实模型失败后继续对话，需在部署环境测进程与上下文。 |
| 同一件事，处处一样 | 工作台、Skill 编辑和模型列表统一称「模型连接」；模型页标题与导航一致。 | 后续新增入口继续复用同一术语和状态含义。 |
| 按下去有回应，再按能收回 | 提交、保存、连接测试已有进度与结果提示；场景 AI 修改支持撤销。 | 可逆开关与归档的恢复能力分开验收。 |
| 不打断人手上的事 | 执行中允许提前填写下一条内容；模型缺失或场景试运行不可用时留在当前页面。 | 检查运行中的草稿、附件与切换页面后的保留行为。 |
| 常用的好做，会丢东西的难误碰 | 会话删除与技能文件删除已有确认；本次为模型和场景编辑添加未保存修改的关闭／离开确认。 | 继续检查所有编辑抽屉与跨页导航。 |
| 界面自己说明自己 | 执行中输入提示「当前执行结束后可发送」；场景维护页在无模型时说明试运行条件并给入口。 | 用非开发者完成新建、编辑、试运行任务，记录仍需解释的词。 |

## 本次验证范围

- 前端类型检查、组件状态脚本、生产构建；Runner 类型检查、DSH 契约和模拟模型的真实进程集成检查（含闲置回收后继续对话）。
- 本地浏览器未能启动、云浏览器无法访问本地预览，未将源码与脚本验证表述为人工界面验收。部署环境仍应走登录 → 新建任务 → 执行中填写下一条 → 编辑模型／场景后取消与离开 → 闲置后继续的浏览器验收。

## 仍需独立排期

- 归档会话当前不能恢复；若要让「归档」成为可撤销操作，需要设计存储与恢复接口，不能只改按钮文案。
- 子代理、持续任务与自动执行应以真实用户任务和容量数据决定，不宜因入口可做而提前暴露。
- 线上发布方式未在仓库 CI 中定义；现有 GitHub Actions 仅执行构建和检查。
