# 会话关联代码

## 目标与范围

每次聊天都可以关联一个或多个代码项目，模型在回答时只读检索、阅读这些项目里的真实代码再给出分析。这是聊天级的通用能力，与场景、能力无关，也与会话工作空间无关。

- 代码根目录由环境变量 `FORGE_CODE_ROOT` 配置，默认 `/usr/data/git`。根目录下的每个一级子目录就是一个可选项目。
- 只有用户勾选的项目会挂载给会话。模型只能读，不能修改；需要产出文档、补丁时写入会话工作区。
- 一个会话最多关联 20 个项目。选择和模型切换一样随消息提交：在输入框里改选，发送下一条消息时一起生效。

## 为什么这样设计

DSH 本身没有「多根目录」机制：`working_directory` 只支持一个 cwd，ACP 也会直接拒绝 `additionalDirectories`。但 DSH 的积木已经够用：

| DSH 能力 | 用法 |
| --- | --- |
| `dsh-tool-fs-search` 的 `glob` / `grep` | `path` 参数接受绝对路径，用 ripgrep 检索项目 |
| `dsh-tool-fs` 的 `read` | `file_path` 接受绝对路径，带行号、分页和字节上限；只开 `read`，`write` / `edit` / `apply_patch` / `read_image` 全部关闭 |
| `ctx.tools.guard` | 执行前校验路径，收窄到「会话工作区 ∪ 已关联项目」 |
| `tools/execute` 包装 | 从搜索结果中剔除密钥类文件，交给工具自己的 render 重新生成文本和卡片 |
| `session/resume` | 关联变化时以新配置重启 dsh 进程，接续同一份会话日志 |

所以方案是：把选中的项目作为只读根交给 Runner，由 forge-runtime 的 guard 守住路径边界，再在系统提示里列出项目路径和概览，让模型知道去哪里找代码。没有引入新的检索服务或索引，也不复制代码。

## 数据流

```
前端「关联代码」多选
  └─ 只改输入框中的选择（执行中也可改），不单独保存
  └─ 发送时随消息提交：POST /api/agent/sessions/{id}/turns {codeProjects}
     （与已生效的选择不同才携带；[] 表示全部取消；校验失败整轮拒绝，输入与选择都保留）
控制面 agent_session.code_projects（JSON）
  └─ 每轮把完整列表下发给 Runner：POST /v1/sessions/{id}/stream {codeProjects}
Runner
  └─ 与当前列表比较；有变化就 dispose → 以新配置启动 dsh → session/resume
  └─ 发出 code_projects 事件（项目名、分支、提交），控制面落库
```

控制面不读代码，项目列表由 Runner 读取（代码与 Runner 在同一台机器上）：`GET /api/code/projects` 代理到 Runner 的 `GET /v1/code/projects`，返回 `{root, available, projects:[{name, path, branch?, commit?}]}`。分支与提交直接读 `.git/HEAD`，支持 packed-refs 和 worktree，不依赖 git 命令。

## 系统提示

关联了项目时，系统提示追加「关联代码（只读）」一段：

- 要求先检索、阅读真实代码再回答，引用时给出文件路径与行号；
- 说明 `grep` / `glob` / `read` 的绝对路径用法；
- 列出每个项目：`### 名称 → 绝对路径（git 分支@提交）`，以及概览（顶层目录、`AGENTS.md` / `CLAUDE.md` 前 1200 字、README 前 800 字，单个项目不超过 2400 字）。

概览让模型可以直接定位，不必先盲目 glob。DSH 的 agent-instructions 只加载 cwd 链上的 `AGENTS.md`，所以项目约定由这里注入。

## 安全边界

| 场景 | 处理 |
| --- | --- |
| 访问未关联的项目、根目录或系统路径 | guard 拒绝：只能访问会话工作区与已关联的代码项目 |
| `..` 越界、符号链接指向项目外 | 先解析路径，再对目标或最近的已存在上级取 realpath，必须仍在该项目内 |
| `.git`、`.ssh`、`.aws` 等目录，`.env*`、`.npmrc`、`id_rsa`、`*.pem`、`*.key` 等文件 | 直接 read 或以其为 path 搜索都会被拒绝；`.env.example` 等示例文件放行 |
| 对整个项目 grep / glob | DSH 搜索会包含隐藏与被忽略的文件（只排除 `.git` 等版本库目录），因此对结果再过滤一次，剔除密钥类文件 |
| 写入、编辑 | 只开放 `read`，写工具不注册；项目目录不进入任何写入路径 |
| 项目名 | 只能是一级目录名：不允许路径分隔符、隐藏目录、控制字符；控制面与 Runner 都会校验，不存在时返回 422 |

### 终端命令的边界

上表的路径校验适用于 `read` / `grep` / `glob`，不适用于 Bash 的全部文件访问。终端按命令分类：简单只读命令、经检查的只读串联和 `2>/dev/null` 可自动执行；重定向到其他目标、构建、写入、未知参数或复杂 Shell 语法需要逐次确认，危险命令按既有规则拒绝。审批卡默认展开完整参数，未指定 `workdir` 时使用会话工作区。

命令分类是减少误操作的门控，**不是操作系统级只读隔离或完整 Shell 安全解析器**。终端仍以 Runner 的进程权限运行，批准写操作后可能修改其有权访问的文件；即使是自动放行的只读命令，也不能依赖该分类器实现路径或密钥隔离。对不可信代码或需要强制只读的部署，应由运维另行配置隔离执行环境和只读挂载，并限制敏感文件及网络访问；不要将关联项目标记或提示词当成强制隔离。

## 配置

`data/business.env`（`scripts/setup-sandbox.py` 生成新环境时会写入默认值）或部署环境变量：

```
FORGE_CODE_ROOT=/usr/data/git
```

Runner 每次列项目、校验时都会读取这个变量，修改后重启 Runner 即可生效。根目录不存在时，前端会提示检查配置，聊天不受影响。

## 前端

- 输入框工具栏的「关联代码」按钮打开多选面板：点选即切换，没有确定/取消；不显示根目录路径；项目多于 6 个时出现无边框搜索框；每个项目带分支与提交。已关联但从根目录消失的项目单独列出，点击即移除。
- 已选项目直接显示在按钮上（如 `forge-backend +2`，悬停列出全部）；有未发送的修改时按钮右上角显示小圆点，输入框上方不再另列标签。
- 关联变化的那一轮，消息流中显示分隔线「关联代码（只读）：a、b」或「已取消关联代码」；每条用户消息的 `meta.codeProjects` 记录当轮可读的项目。
- 右侧「能力」面板列出已关联的项目及版本，执行边界会相应说明。

## 验证

- Runner `scripts/check-code-projects.mjs`：项目列举、git 元数据、名称校验、概览、路径收窄、搜索结果过滤（10 项）。
- Runner `scripts/check-business.mjs`：真实启动 dsh，验证关联后重启并带上 `read`、按绝对路径 grep / read、未关联项目被拒、密钥与符号链接被拒、整项目搜索不泄露密钥、切换多项目下一轮生效、清空后撤销。
- 后端 `tests/test_session_code.py`：每轮下发完整列表、两轮之间与执行中修改、非法选择不留记录、请求模型边界、Runner 客户端请求体。
- 前端 `check-conversation-drafts.mjs`、`check-turns.mjs`：新会话草稿随首轮提交、已有会话的修改随下一条消息提交（执行中可选、切换会话保留、未修改不重发、清空显式提交、被拒后保留）、分隔线计算。

## 后续可选

- 大型仓库可增加按项目委派的 subagent，并行分析多个仓库。
- 关联指定分支或提交（目前读取工作区当前检出的内容）。
- 按用户或部门限制可关联的项目。
