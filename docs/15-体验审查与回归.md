# 体验审查与回归

## 本次范围与修复

依据“系统承担复杂性、减少打断、反馈真实、保护用户输入”的原则，沿工作台 / 会话、空间、模型、策略与能力说明梳理关键路径，并结合现有草稿、会话、文件与流式测试排查。此次优先修复影响数据和信任的具体问题，不代表所有页面都已逐项完成体验验收。

- 模型编辑：关闭、切页或刷新时保护未保存的配置；查看已保存密钥不算修改。服务端已保存但刷新状态失败时明确区分，不误导重复提交。
- 执行策略：读取失败时不暴露默认值供保存，提供重试；清理过期文件前说明不可撤销并要求确认。
- 空间工具：切换空间立即清除旧列表；旧空间操作的回执不覆盖新空间；读取失败可重试。
- 复制：剪贴板不可用或拒绝时提示失败，JSON 节点和 Markdown 预览不再显示虚假的成功。
- 能力说明：终端命令不再声称会逐次确认或完全拦截所有高危命令；说明实际隔离边界。

## 验证方式

`npm --prefix frontend test`、`npm --prefix frontend run typecheck`、前端构建和格式 / 图标 / 色彩 / 字号 / 主题令牌检查；`scripts/check-ux-browser.py` 对构建前端使用隔离 HTTP 夹具，在 Chromium 中验证草稿保护、保存成功后刷新失败、策略读取失败重试、取消清理和跨空间迟到回执。浏览器脚本需要 Playwright、Chromium 和正在运行的前端；不连接真实服务或模型。构建在内存较小的环境可能需要 `NODE_OPTIONS=--max-old-space-size=4096`。

## 未完成与上线边界

- 空间编辑弹窗、执行策略及其他管理表单仍需系统性的未保存修改保护，场景维护等流程还需逐页交互验收；本次未声称全面修复所有体验问题。
- 本次夹具回归不等于真实模型、真实后端及生产环境验收，也不替代独立审查。多人权限与生产隔离等限制以项目 README 为准。
- 合并分支和生产部署是两件事。仓库现有工作流只执行检查，未定义生产部署；在真实环境、部署流程和独立审查未确认之前，不应宣称已上线。
