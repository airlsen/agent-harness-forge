# 能力构建与场景装配

## 目标与范围

把 Skill、MCP 服务和联网搜索真正接入会话执行。它们既可以**在场景中绑定**，也可以**在聊天中临时选用**。一轮实际生效的扩展能力等于场景绑定的部分加上聊天临时选择的部分（取并集）。

| 能力         | 场景绑定                  | 聊天临时选用          | DSH 实现                                                   |
| ------------ | ------------------------- | --------------------- | ---------------------------------------------------------- |
| Skill        | ✓（发布时冻结到当前修订） | ✓（取最新已发布修订） | `dsh-skill` 注册表 + `dsh-tool-skill` 的 `skill` 工具      |
| MCP 服务     | ✓                         | ✓                     | 每个服务挂一个 `dsh-mcp-client`（stdio / Streamable HTTP） |
| 联网搜索     | ✓                         | ✓                     | `dsh-web` + `dsh-tool-web`（`web_search` / `web_fetch`）   |
| 平台基础工具 | 默认开启                  | —                     | forge-runtime（时间、会话文件读写）                        |
| 受管插件     | ✓（维持原机制）           | —                     | forge-plugin-bridge                                        |

本方案取代 `docs/10-MCP接入一期.md` 中“不支持 stdio / 尚未接入场景装配和聊天工具调用”的描述。旧版 SSE 仍然只能测试连接：DSH 的 MCP 客户端不支持 SSE。

### 联网搜索：DSH 支持吗？

支持。DSH 官方提供 `dsh-tool-web`（`web_search` / `web_fetch` 两个工具），搜索提供方是 `dsh-web-search-deepseek`（DeepSeek 官方联网搜索，走 Anthropic 兼容接口），也可以选择 `dsh-web-deepseek-api`（DeepSeek Search API）。网页读取由 `dsh-web-fetch-http` 完成，只访问公网地址（防 SSRF）。

- 需要一个 DeepSeek API Key。可以在治理中心单独填写；不填时复用模型中心里地址为 `api.deepseek.com` 的已启用模型的密钥。
- 每次搜索大约相当于一次模型调用，会按模型调用计费。
- 没有密钥时，如果开启了网页读取，就只能读网页，不能搜索。

## 为什么这样设计

1. **Skill 本质上是文本。** 不需要新的执行器，交给 DSH 的 Skill 注册表即可。模型通过 `skill` 工具按需加载正文；用户在消息里输入 `/名称` 也能直接调用。控制面同时下发完整原文与全部附加文件，Runner 按「修订号-内容哈希」把整个 Skill（`SKILL.md` + `references/`、`assets/`、`scripts/`）物化为会话工作区之外的只读快照目录，内容与修订逐字节一致；模型按正文中的相对路径用 `read` 读取，脚本只能经 `skill_run_script` 逐次审批运行。
2. **MCP 凭据不进入 Bundle。** 场景快照只记录服务引用（编号），凭据、命令和工具清单每轮实时解析。这样轮换密钥、停用服务都能立即生效，历史快照里也不会留下密钥。
3. **与关联代码、模型切换一致：随消息提交，从该轮生效。** 输入框里的选择不单独保存，发送消息时一起提交。Runner 每轮收到完整的能力集合并计算指纹（覆盖全部字段，含凭据；Skill 内容由快照标识代表）。指纹有变化，就以新配置重启 dsh 并 `session/resume` 接续同一会话。
4. **不可用不阻塞。** 某个 Skill 取消发布或附加文件缺失/损坏、MCP 服务停用或联网被关闭时，本轮跳过该项并记录在 `unavailable` 中（Skill 附带具体原因 `reason`），对话照常进行，前端会提示“未生效”。缺文件的 Skill 不会以残缺目录装配。

## 数据模型

### 场景（`ScenarioPayload.capabilities`）

```jsonc
{
  "skill_ids": [3, 5], // 最多 20 个
  "mcp_server_ids": [2], // 最多 10 个
  "web_search": true,
  "builtin_tool_names": [], // 基础工具始终开启，保留字段只为兼容
  "project_ids": [], // 已废弃：关联代码改为聊天中按会话选择
}
```

场景装配（`ScenarioAssembler.compile`）会写入 `bundle.meta`：

- `skills`：每项为 `{id, revisionId, version, name, title}`，冻结到当前已发布修订（修订不可变）。
- `mcpServers`：每项为 `{id, name}`，只是引用。
- `webSearch`：布尔值。

保存草稿时就会校验：Skill 必须已发布；MCP 服务必须已启用、连接测试通过、传输方式为 stdio 或 Streamable HTTP，并且已发现工具。`ScenarioPayload.model` 仍会被接收但会被忽略，模型在聊天中选择。

### 会话（`agent_session.capability_selection`）

```json
{ "skillIds": [7], "mcpServerIds": [], "webSearch": false }
```

这是聊天临时选择的部分，不包含场景绑定项，随消息提交后保存。限制为最多 20 个 Skill、10 个 MCP 服务，且不能重复。提交时只校验新增项：已保存的项即使后来下线，也允许原样保留（每轮解析时跳过）。

| 情况             | 返回                 |
| ---------------- | -------------------- |
| Skill 未发布     | 422 “尚未发布”       |
| MCP 服务不可运行 | 422 “MCP 服务不可用” |
| 联网未开启       | 409 “联网搜索未开启” |

## 接口

| 接口                                                    | 说明                                                                                                  |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `GET /api/capabilities/options`                         | 聊天与场景编辑器共用的可选项：已发布 Skill、可运行的 MCP 服务（含工具与权限）、联网状态。不含任何密钥 |
| `POST /api/agent/sessions/{id}/turns` `{capabilities?}` | 临时选择随消息提交（与已生效的选择不同才携带）；省略时沿用已保存的选择；校验失败整轮拒绝，不留记录    |
| `GET/PUT /api/governance/web-search`                    | 联网设置：`enabled`、`provider`、`baseUrl`、`apiKey`（只写）、`clearKey`、`fetchEnabled`              |
| `PATCH /api/registry/mcp-servers/{id}` `{enabled:true}` | SSE 服务启用时返回 409                                                                                |

会话详情返回两部分：

- `capabilities`：聊天临时选择的部分。
- `scenarioCapabilities`：`{skills, mcpServers, webSearch}`，即场景快照中绑定的部分，前端据此把这些项显示为“场景”且不可取消。

轮次回执返回：

- `capabilities`：保存后的选择。
- `activeCapabilities`：本轮生效的摘要，同时写入用户消息的 `meta.capabilities`。

## 每轮解析（`capability_service.resolve`）

```
bundle.meta（场景绑定） ∪ capability_selection（聊天选择）
  ├─ Skill：场景项按 revisionId 读取冻结修订，聊天项读取最新已发布修订
  │    名称规范化为 DSH 语法（小写 kebab-case），失败时回退为 skill-<id>，冲突时追加 -<id>
  │    document = 完整原文（含 front matter，写成快照里的 SKILL.md）；content = 去掉 front matter 的正文（注册到 DSH）
  │    附带 references/、assets/、scripts/ 文件（最多 20 个，单个 120KB，合计 512KB），按字节原样读取、不截断
  │    任一文件缺失、不可读、非 UTF-8 或超限：只把这个 Skill 记入 unavailable（含 reason），其余能力照常装配
  ├─ MCP：重新检查是否可运行；解密凭据，组装 stdio 命令或 HTTPS 地址
  │    工具权限：annotations.readOnlyHint === true 记为 read，其余记为 approval（每次调用前需确认）
  │    serverName 不合 DSH 语法时改名为 mcp<id>
  └─ 联网：读取平台设置；密钥优先取单独配置，其次取 DeepSeek 模型密钥
→ (runtime caps：下发给 Runner；summary：写入消息，不含正文与密钥)
```

`summary` 的结构如下：

```json
{
  "skills": [
    { "id": 7, "name": "weekly-report", "title": "周报", "version": 3, "revisionId": 21, "snapshot": "21-3f9a0c1d2e4b", "source": "chat" }
  ],
  "mcp": [
    {
      "id": 2,
      "name": "Jira",
      "serverName": "jira",
      "transport": "stdio",
      "source": "scenario",
      "tools": 5,
      "approvalTools": 2
    }
  ],
  "web": { "search": true, "fetch": true, "source": "scenario" },
  "unavailable": [{ "kind": "skill", "id": 9, "title": "旧规范", "reason": "缺少附加文件：references/rules.md" }]
}
```

`revisionId` 与 `snapshot` 记录本轮实际装配的修订和 Runner 快照目录名，便于回溯“这一轮模型看到的是哪一版 Skill”。`snapshot` 由控制面（`capability_service.skill_snapshot_id`）与 Runner（`capabilities.skillSnapshotId`）用同一算法计算：`<revisionId>-<sha256 前 12 位>`，哈希依次覆盖 `SKILL.md`、原文，以及按路径排序的每个附加文件的路径与内容（各项以 NUL 分隔）。两端测试固定同一夹具的结果。

## Runner 契约

创建会话（`POST /v1/sessions`）和每一轮（`POST /v1/sessions/{id}/stream`）都携带本轮完整的 `capabilities` 集合。Skill 有两种形式：

- **全文**：带 `document`、`content`、`files`，以及控制面算出的 `snapshot`（Runner 自己再算一遍，不一致则 422）。
- **快照引用**：只有 `{name, title, description, revisionId, snapshot, source}`，不带原文与附件。

```jsonc
{
  "skills": [
    { "name": "weekly-report", "title": "周报", "description": "…", "revisionId": 21, "snapshot": "21-3f9a0c1d2e4b", "document": "---\nname: weekly-report\n…", "content": "…", "files": [{ "path": "references/template.md", "content": "…" }, { "path": "scripts/check.py", "content": "…" }], "source": "chat" },
    { "name": "translate", "title": "翻译", "description": "…", "revisionId": 8, "snapshot": "8-90ab12cd34ef", "source": "scenario" }
  ],
  "mcp": [
    { "serverName": "jira", "title": "Jira", "source": "scenario", "transport": "stdio", "command": "npx", "args": ["…"], "env": { "JIRA_TOKEN": "…" }, "tools": [{ "name": "search", "permission": "read" }] },
    { "serverName": "docs", "transport": "streamable-http", "url": "https://…", "headers": { "Authorization": "…" }, "tools": [ … ] }
  ],
  "web": { "search": true, "fetch": true, "provider": "deepseek-official", "apiKey": "…", "baseUrl": null, "source": "scenario" }
}
```

### Skill 内容按快照传递（不再每轮传全文）

修订不可变、附件只写不改，快照名又包含内容哈希，所以"同一快照 = 同一内容"，可以放心缓存：

1. **控制面**（`capability_service._runtime_skill`）在内存里记住算过的快照（键 = 修订编号 + 原文哈希 + 文件清单，最多 4096 条）。
   - 首次使用某修订：严格读取全部文件，计算快照，下发全文；
   - 之后每轮：只发快照引用，不读文件内容，只检查附件是否仍在磁盘上（被删除时与首次读取一样，只跳过这个 Skill 并记录原因）。
2. **Runner**（`DshKernel.resolveTurnCapabilities`）解析引用时先找本会话当前能力，再找进程内缓存 `SkillContentCache`（按最近使用淘汰，总量 64 MB；所有会话共享）。全文形式解析后也记入缓存。
3. **缺内容时补发**：Runner 找不到某些快照（重启或缓存淘汰）时，在开始执行前返回 `409 {code: "SKILL_CONTENT_REQUIRED", missingSkills: [...]}`。控制面（`runner_client` 抛出 `SkillContentRequired`）用 `expand_skills` 只为这几个 Skill 补发全文，然后重试一次，用户无感。补发时文件已不可用则本轮报错并忘记该快照，下一轮按常规标记为不可用。
4. **新建会话**：用全文（或引用）创建 Runner 会话后，紧接着的第一轮只发引用。
5. **指纹**：Skill 只按 `snapshot` 与元数据参与指纹，不再每轮对全文做哈希；引用和全文解析出的指纹相同，只发引用不会触发重启。
6. **兼容**：新 Runner 仍接受旧控制面的全文格式（没有 `snapshot` 时自己计算）。新控制面会发引用，需配合新 Runner（`/v1/runtime` 的 `capabilities.skillSnapshots: true`）。

模型这一层不受影响：上下文里每轮只有 Skill 目录，正文由 `skill` 工具、附件由 `read` 按需加载。

Runner（`src/kernel/capabilities.ts`）先严格校验，校验失败直接拒绝本轮：

- 名称语法与数量、字节上限；
- 远程地址必须是 HTTPS；
- 拒绝 SSE；
- 拒绝空工具清单。

校验通过后按以下方式装配：

- **工具白名单**：在原有基础工具规则之后，依次追加 `skill`、`web_search` / `web_fetch`、`mcp__<server>__<tool>`（只包含控制面允许的工具）。权限为 `approval` 的 MCP 工具每次调用前都会发出确认请求，复用现有审批流程。
- **Skill**：`forge-skills-plugin` 在 `agent/created` 时把正文注册进 `dsh-skill` 注册表，`resourceBase` 始终是该 Skill 的快照目录。快照目录为 `DATA/<id>/skills/<name>/<revisionId>-<hash>/`，包含 `SKILL.md`（`document` 原文；旧控制面不下发时不写，绝不从正文重建）与 `references/`、`assets/`、`scripts/` 文件，文件权限 0400：
  - 每个 Skill 都有快照目录，只有 `SKILL.md` 的 Skill 也一样（此时不开放 `read`）；
  - 先写临时目录再原子改名，同名快照（同内容）直接复用；
  - 启动时不再整体删除 `skills/`：旧修订的快照与会话日志一样保留在会话数据目录中（不属于工作区，不受产物保留期清理影响），接续会话时历史里的旧路径仍可追溯；但 forge-runtime 的只读根只包含本次装配的快照目录，模型读不到旧快照；系统提示也要求以本次 `skill` 结果给出的目录为准；
  - 脚本仍只能通过 `skill_run_script` 运行（逐次审批、bwrap 隔离、快照目录只读挂载到 `/skill/current`），写出 `SKILL.md` 不带来新的执行权限；
  - 字段 `document`、`revisionId` 可选，旧控制面不下发时照常装配（快照修订号记为 0）。
- **MCP**：每个服务一个 `dsh-mcp-client` 实例。stdio 进程的工作目录是 `DATA/<id>/mcp`（权限 0700）。密钥只通过子进程环境变量传递，不写入磁盘或日志。
- **联网**：先加载 `dsh-web` 和所选的搜索提供方，再加载 `dsh-web-fetch-http` 与 `dsh-tool-web`。API Key 通过环境变量注入，不写入 dsh 配置文件。
- **系统提示**：追加能力说明，包括可用 Skill 列表与 `/名称` 用法、MCP 工具需确认的提示，以及联网时需注明来源的要求。
- **事件**：`capabilities`（摘要，Skill 项含 `revisionId` 与 `snapshot`）和 `skills_loaded`。

## 安全边界

- **MCP stdio**：按用户要求不关闭。命令以 Forge 服务进程的权限启动，只有管理员能导入、测试和启用。连接测试（以及 Runner 启动）时，子进程不会继承父进程中名称含 `KEY|PASSWORD|SECRET|TOKEN` 的环境变量，以及 `FORGE_` / `DSH_` 前缀的变量，只合并该服务自己配置的 env。
- **MCP 远程**：沿用一期的 SSRF 限制（只允许 HTTPS 和公网地址，不跟随重定向）。
- **工具权限**：未声明 `readOnlyHint` 的 MCP 工具一律视为需要确认。
- **网页读取**：`dsh-web-fetch-http` 固定解析结果，只访问公网地址。
- **密钥**：消息、回执、事件、轨迹和 Bundle 中都不包含密钥与 Skill 正文。联网 API Key 加密存储，只写不读。

## 前端

- **聊天输入框「扩展能力」**（`CapabilityPicker`）：按 Skill / MCP / 联网分组。场景绑定项显示为已勾选、不可取消，并带“场景”标签；已下线的已选项单独列出，方便取消；联网未开启时不可勾选。点选即切换，没有确定/取消，随下一条消息提交（执行中也可选）。当前选择直接显示在按钮上（如“联网搜索 +1”），有未发送的修改时显示小圆点；输入框上方不再另列标签。
- **会话「能力」面板**：依次列出基础工具（默认开启）、Skill、MCP 服务、联网和执行边界。每一项都标明来源（场景绑定 / 临时选用）以及是否已下线；面板展示已生效的选择，输入框中有未发送的修改时提示“随下一条消息生效”。
- **消息流**：不插入扩展能力、模型切换等分隔条，只保留对话本身；工具名中文化，MCP 工具显示为“服务 · 工具”。
- **未生效提示**：最近一轮因下线、停用或平台关闭而未装配的项（用户消息 `meta.capabilities.unavailable`），以及预计下一轮会被跳过的项，在「能力」面板中逐项以橙色标记；顶部「能力」按钮显示“N 项未生效”。全部未生效时后端同样记录摘要。
- **场景编辑器**：基础工具标注“平台基础能力（默认开启）”，提供 Skill、MCP 服务、联网三个选择区，演示插件标注“演示数据”。卡片与详情展示绑定的扩展能力。
- **治理中心**：新增“联网搜索”设置卡片，包括开关、搜索服务、API Key（显示密钥来源，可清除）、服务地址和网页读取开关。
- **能力中心**：SSE 服务提示“仅测试连接，暂不可在会话中运行”，且不能启用；基础工具标注“平台基础能力（默认开启）”。
