# 好坏对照：周报 Skill

## 差的版本

```markdown
---
name: weekly-report
title: 周报
description: 写周报
---
# 周报
## 目标
帮用户写周报。
## 步骤
1. 了解用户本周工作
2. 整理成周报
3. 注意格式规范、语言简洁
```

问题：

- description 只写了"写周报"，没有触发条件和常用说法，用户说"帮我总结下这周"可能不会被用上
- "了解本周工作"：从哪了解？用户没提供时怎么办？
- "整理成周报"：什么结构？写多长？
- "注意格式规范"：没有标准，没法执行，也没法检查
- 没有不适用的情况，没有输出样例

## 好的版本

```markdown
---
name: weekly-report
title: 个人周报
description: 用户要写周报、周总结、本周工作汇报时使用。把零散的工作记录整理成结构固定的个人周报。
---
# 个人周报
## 适用 / 不适用
- 适用：个人周报
- 不适用：团队周报、项目月报 → 告诉用户本 Skill 只处理个人周报
## 开始前确认
需要本周工作记录。用户没提供时，请用户列出本周做的事，一行一件，不要求格式。
## 步骤
1. 归类：把每条记录归入"完成 / 进行中 / 问题"三类（完成标准：每条都有归属）
2. 补结果：完成项写清产出或数字；缺少时标"待补充"，不编造
3. 写下周计划：从"进行中"推出 3 条以内
## 必须问人的情况
记录里出现延期或风险时，问用户是否写进周报
## 输出要求
三个小节：本周完成 / 问题与风险 / 下周计划，每条一行，全文不超过 300 字。
样例：
- 完成用户导入功能上线，覆盖 3 个省份
## 交付前检查
- 没有编造的数字
- "待补充"已列出提醒用户
```

## 改进点

触发条件写全；输入缺失有处理方法；"整理"拆成可检验的三步；"格式规范"换成具体结构和字数；补了边界、问人点和样例。
